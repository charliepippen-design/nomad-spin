# Languages

English is the default language and keeps every URL it has always had. Other
languages live under a prefix with translated path segments:

| English | Italian |
| --- | --- |
| `/` | `/it` |
| `/destinations/lisbon` | `/it/destinazioni/lisbon` |
| `/guides/living-in-lisbon` | `/it/guide/vivere-a-lisbona` |
| `/find-your-base` | `/it/trova-la-tua-base` |

No paid service or plugin is involved: translations are files in this repo.

## The one rule

**A page exists in a language only when it has been translated and marked
`"status": "published"`.** Everything else follows from that:

- no URL, no prerendered HTML, no sitemap row and no hreflang for a page that
  is not translated;
- links written as English paths lead to the translated page when it exists and
  to the English page when it does not;
- the language menu opens the same page in the chosen language when it exists;
  otherwise the reader stays on the English page, a one-line notice says so in
  their language, and the rest of the site stays in their language.

## Where things are

| What | Where |
| --- | --- |
| Languages, published languages, translated URL segments | `src/i18n/config.ts` |
| URL mapping, hreflang | `src/i18n/paths.ts` |
| Interface text | `src/locales/<lang>/<area>.json` (English in `en/` is the source) |
| City text (name, pros, cons, visa note…) | `content/cities/<lang>/<cityId>.json` |
| Guides | `content/guides/<lang>/<english-slug>.md` + `.json` (own slug, title, SEO) |
| Which pages exist per language (generated) | `src/locales/manifest.generated.json` |

In code: `useT()` / `useLocale()` in React components, `getT(locale)` in plain
modules, `Link` / `NavLink` / `useNavigate` from `@/i18n/Link` with English
paths. Numbers, dates, months and country names come from `src/i18n/format.ts`.

## Translating (with Claude or any assistant, or by hand)

```
npx tsx scripts/i18n-status.ts          # what is missing or out of date, per language
npx tsx scripts/i18n-status.ts it --stamp   # record the English version each translation was made from
```

1. **Interface text**: add the key to `src/locales/en/<area>.json`, then to
   every published language. A missing key fails type-checking and the tests.
2. **A city**: create `content/cities/<lang>/<cityId>.json` with the same number
   of pros, cons and legal notes as the English record. Start with
   `"status": "draft"`.
3. **A guide**: create `content/guides/<lang>/<english-slug>.md` and `.json`.
   Keep internal links as English paths; they are rewritten when the page is shown.
4. Read it through, set `"status": "published"`, run the status script with
   `--stamp`, commit. The build picks it up (`scripts/sync-locales.ts`).

When the English text changes later, the status report lists the translation as
out of date. It stays online until someone updates it and stamps it again.

A useful request to an assistant: *"Run the i18n status script for Italian,
translate the next 20 cities that are not started, keep them as drafts and show
me the result."*

## Adding a language

1. `src/i18n/config.ts`: it is already listed for Spanish and French (names,
   URL segments). For a new one add it to `LOCALES`, `LOCALE_INFO`, `SEGMENTS`.
2. Copy `src/locales/it/` to `src/locales/<lang>/` and translate the JSON files.
3. Translate the cities and guides you want to launch with.
4. Add the language to `PUBLISHED_LOCALES`. Routes, menu entry, hreflang,
   sitemap rows and prerendered pages appear from that line alone.

## Checks

`src/test/i18n.test.ts` fails when a published language misses a key, has a
placeholder that differs from English, when URL segments collide, or when the
generated files are not in sync with `content/`.
